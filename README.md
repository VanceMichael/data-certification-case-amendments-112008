# 境外认证联办门户的场址补报与回执

这里是可离线启动的合成上游，所有编号、时间和凭据都用于联调。

## 本地运行

使用 Node.js 22.23.4。`npm ci` 安装锁定依赖，再用 `npx playwright install chromium` 准备 Chromium。使用 Linux 时需有 Chromium 系统库。

```sh
npm run source   # 合成联办门户，默认 http://127.0.0.1:4173
npm start        # 代办控制台，默认 http://127.0.0.1:4180
npm test
```

`npm start` 用于在浏览器里办理；控制台通过 Playwright 在 Chromium 内操作门户页面，不使用门户以外的接口。`SOURCE_URL` 可把控制台指向别处的来源，`APP_PORT` 设置控制台端口。控制台只在内存中保存会话，重启即清空。

## 代办怎么用

1. 用企业提供的申请号、目标市场、计划审核日、迁移工序、旧场址、新场址和企业给的目录显示名填写变更资料，点「载入资料」。
2. 点「核对目录与申请」：代办会读地址目录页与申请详情页，把候选新场址、已受理的旧址范围、保留的未迁移工序一起列出。目录里没有有效新场址时会停在可继续办理的状态，并说明缺哪一边凭据。
3. 点「查看复核页」：代办把核定结果填进门户复核表单，读回门户实际展示的版本、补加、终止和保留范围。申请页没列出旧址受理范围时，以复核页显示的上下文为准；复核页若要求终止未迁移工序，代办停止提交。
4. 填写经办人并「按当前屏幕内容批准」。批准绑定的是复核页文字摘要、受理版本和目录摘要。
5. 「提交本次补报」前代办会重读目录和申请页；资格目录、申请版本或拆分范围有任何变化，旧批准立即失效，页面退回复核。
6. 提交后按申请号与门户显示的变更编号查受理记录：全部受理、待回执、部分受理分别落到不同状态。部分受理时「读取剩余办理」，由经办人重新确认后只提交未完成的一边；整单不会再次提交。
7. 页面右侧依次显示：变更资料核自哪一页（URL、时间、摘要）、批准了哪些场址和工序、门户实际接收了哪部分、剩余事项由哪位经办人确认，以及完整办理记录。

不同终端分别启动服务和执行独立来源测试。默认地址为 `http://127.0.0.1:4173`，可通过 `SOURCE_PORT` 设置端口，也接受通用的 `PORT`，同时设置时以 `SOURCE_PORT` 为准。`GET /health` 用于确认来源服务已就绪。来源使用进程内演练时钟，启动时处于 `draft`。用 `PUT /_source_clock?step=update` 推进到下一阶段，`GET /_source_calls` 查看本实例收到的业务请求。可查阶段为 `draft`、`update`、`partial`、`settled`。重启服务会重置时钟和请求记录。预置的源端回执按演练阶段出现，和本地应用是否已处理某次回执是两回事。
`npm test` 覆盖来源响应、规则解析、代办状态机与 Chromium 页面联调。

## 来源约定

门户首页是 `/cases`，含申请详情、审核地址目录和受理记录入口。地址与工序业务编号显示在表格正文，门户中的审核日采用当地公历日，日期范围结束日不包含在内。合作方给代办人员的变更资料在 `fixtures/amendment.json`，变更编号与申请号都是门户用于认领的索引。
同一个复核表单既接受一对地址补报，也允许只提交尚未完成的半边；页面清楚显示门户当时的申请版本和操作范围。这是离线联调站点，其中超时或部分受理由演练时钟控制，所有收到的表单提交都可在 `/_source_calls` 按原请求查看。
